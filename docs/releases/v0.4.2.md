# Cangze 0.4.2

Security and mechanism hardening release for Cangze (藏泽), the open-source AI hub for Home Assistant.

> **Prerelease.** This release tightens authorization boundaries, protects backup/provider surfaces, improves model controls and adds read-only Home Assistant configuration inspection.

## Highlights

- High-risk lock and garage/gate/door cover actions remain approval-gated.
- Sensitive management APIs require a browser administrator session; device tokens remain available for normal device operations.
- Audit and approval data are redacted before persistence or publication.
- Backup paths, temporary files and master-key fingerprints are validated and protected.
- Provider URLs reject embedded credentials/query fragments; discovery errors are sanitized and obvious metadata targets are blocked.
- Subagent overview metadata respects read permissions; trigger payloads are bounded untrusted data; rule call quotas persist across restarts.
- New sessions expose model and thinking-level selection, including all supported reasoning levels; mobile session settings expose the same controls.
- Native Home Assistant automation, script and scene configuration can be inspected in a responsive read-only drawer.
- Malformed HTTP/stream responses recover safely; key query errors, mobile drawers and keyboard interactions are improved.

## Install or upgrade

```bash
mkdir cangze && cd cangze
VERSION=0.4.2
curl -fsSLO "https://github.com/IGNGserver/cangze/releases/download/v${VERSION}/compose.yaml"
curl -fsSL "https://github.com/IGNGserver/cangze/releases/download/v${VERSION}/env.example" -o .env
docker compose up -d
docker compose logs cangze | grep -i bootstrap
```

Image: `ghcr.io/igngserver/cangze:0.4.2` (also `:next`), `linux/amd64` and `linux/arm64`.
