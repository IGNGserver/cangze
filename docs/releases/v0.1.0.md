First public prerelease of Cangze (藏泽), an open-source AI hub for the Home Assistant you already run.

> **Prerelease.** Feature complete for a first version and covered by unit, end-to-end and real Home Assistant
> integration tests, but young. Back up regularly (_Settings → Data & backup_) and report issues.

## Install

```bash
mkdir cangze && cd cangze
curl -fsSLO https://github.com/IGNGserver/cangze/releases/download/v0.1.0/compose.yaml
docker compose up -d
docker compose logs cangze | grep -i bootstrap
```

Image: `ghcr.io/igngserver/cangze:0.1.0` (also `:next`), `linux/amd64` and `linux/arm64`. See
[DEPLOYMENT.md](https://github.com/IGNGserver/cangze/blob/v0.1.0/docs/DEPLOYMENT.md).

## What's in it

- **Home Assistant over WebSocket and REST**: no add-on and no integration to install. States, registries
  (areas, floors, devices, labels), history, logbook, statistics, templates, cameras, calendars, to-do
  lists, automations, scripts and scenes. Every write goes through one gateway that expands targets to
  explicit entities, checks permissions and conflicts, and records an audit entry.
- **Sessions**: any number of equal conversations with their own model, thinking level, instructions and
  context. Branching (edit and regenerate), steering and queued follow-ups while the model works, automatic
  context compaction, live tool calls, image input for vision models, and Markdown/JSONL export.
- **Models**: built-in providers (OpenAI, Anthropic, DeepSeek, Qwen, Gemini and more) plus any
  OpenAI- or Anthropic-compatible endpoint (Ollama, vLLM, LM Studio, gateways), with model discovery,
  connection tests and per-model token and cost accounting.
- **Approvals**: unlocking, disarming, opening garage doors and configuration changes ask first, in the
  session or the notification center. Risk levels are configurable per domain.
- **Subagents**: persistent background agents with revisioned definitions, their own memory and
  conversation, and cron, interval, Home Assistant state and event triggers. Permissions are default deny and
  enforced by the backend (entities, areas, devices, labels, services, parameter bounds, time windows, rate
  limits). Conflict handling covers human priority, agent priorities, flap and loop protection, and run
  leases. Run history shows every tool call.
- **Operations**: scheduled and manual backups, optionally encrypted with a passphrase and able to carry the
  master key. Restore happens from the UI with a pre-restore copy. Also included: system log, audit log and
  usage views, data retention, a notification center and a first-run wizard.
- **Security**:
  - one admin key, exchanged for a one-time bootstrap code on first start;
  - HttpOnly SameSite=Strict sessions and revocable device tokens;
  - plain HTTP is allowed from private networks only, and public clients need HTTPS (an optional Caddy
    profile is included);
  - Host and Origin checks against DNS rebinding and CSRF;
  - strict CSP and security headers;
  - credentials encrypted with AES-256-GCM.
- **Clients**: the whole UI runs on the documented `/api/v1` REST API and `/api/v1/stream` WebSocket
  ([API.md](https://github.com/IGNGserver/cangze/blob/v0.1.0/docs/API.md),
  [openapi.json](https://github.com/IGNGserver/cangze/blob/v0.1.0/docs/openapi.json)). Pairing codes and
  device tokens for a native app are already in place.

## Known limitations

- The Android client is planned for a later release; the API and pairing flow it will use are in place.
- Schedules, permission time windows and backups follow the Home Assistant time zone. The web UI shows
  timestamps (for example "next trigger") in the browser's local time.
- The image tag `latest` will only exist after the first formal (non-prerelease) release; `compose.yaml`
  pins `0.1.0`.
- Cangze needs a long-lived access token. Use a dedicated Home Assistant user: a non-administrator user
  disables the configuration tools (automations, scripts, scenes).
